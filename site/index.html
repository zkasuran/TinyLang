The Narrative

From Spec to Ship

TinyLang wasn't coded and then documented. It was specified, designed, built and verified — in that order, with Kiro driving every phase.

Phase 1 — Specification
21 spec files written across 7 subsystems before any implementation. Requirements with acceptance criteria. Design documents with architecture diagrams. Task lists with checkboxes. The language grammar. The operator precedence table. All in .kiro/specs/.
Phase 2 — Core Engine
Lexer → Parser → Tree-walk Interpreter. The reference implementation, built test-first, with educational error messages that tell beginners what went wrong and how to fix it. 6 data types, classes with inheritance, closures, pattern matching.
Phase 3 — Compiler & VM
A 63-opcode bytecode compiler with constant folding, dead code elimination and peephole optimization. A stack-based VM with call frames, open/closed upvalues, try/catch handler stack, and re-entrant dispatch for higher-order callbacks. Cross-validated against the interpreter with 191 differential tests.
Phase 4 — The Toolchain
17 CLI commands. A debugger with breakpoints, stepping and watch expressions. A formatter that proves it never changes meaning. A linter with auto-fix. A built-in test framework. A WebAssembly target that genuinely assembles and runs. A 480KB Web IDE.
Phase 5 — Correctness Audit
The VM shipped producing wrong answers — fibonacci(20) returned 53. The 42 existing tests all passed. What caught it: a differential suite asserting byte-identical output between both backends. Six correctness bugs found and fixed. The Web IDE was dead on load in every browser. The formatter silently deleted try/catch blocks. All discovered by running the artifacts, not inspecting the code.
The Language

Not a toy. A real language.

Classes, closures, pattern matching, f-strings, try/catch, pipe operator, optional chaining, enums, destructuring, ranges, WebAssembly — and educational errors that help beginners learn.

fibonacci.tiny
fn fibonacci(n) { if n <= 1 { return n } let a = 0 let b = 1 for i in 2..n + 1 { let temp = b b = a + b a = temp } return b } // Three ways to run: print(f"fib(20) = {fibonacci(20)}") // → 6765 // tinylang compile fib.tiny → fib.tinyc // tinylang exec fib.tinyc → 6765 // tinylang wasm fib.tiny → fibonacci(20) === 6765 ✓

Correctness

1,003 tests. Zero exclusions.

Test count is not the metric. Cross-validation is. The VM passed 42 tests while producing wrong answers. What caught it: comparing both backends against each other.

Differential Testing

191 tests run the same program through interpreter, VM, and optimized VM — asserting byte-identical stdout. Zero exclusions: every example, every feature, every edge case.

WASM Verification

34 tests assemble the emitted .wat with wat2wasm, validate it, instantiate it under WebAssembly, call the function and assert the numeric result. fibonacci(20) === 6765.

Formatter Proofs

96 tests re-parse the formatted output and compare ASTs for structural equivalence. Comments are verified separately. The formatter throws rather than return unsafe output.

Round-Trip Safety

Every example program is formatted, then run — the output must be identical to running the original. A format that changes behaviour is a build failure, not a style choice.
